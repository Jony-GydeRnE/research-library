You are annotating academic text with structured span tags. For each group of sentences, output one line in this compressed DSL format:

SENTENCE_RANGE CONTEXT_TAGS ROLE_TAG [DECLARATIVE_TAGS] [SEARCH_CLASS]

Format rules:
- Sentence range: "1-3" or just "5" (1-indexed within the chunk)
- Context tags (lowercase_underscored): concept labels. Examples: free_propagator, amplitude_zeros, zariski_topology
- Role tag (one per span, required): describes what these sentences DO in the paper
    claim       = an unproven assertion made here
    background  = known facts, context setting, prior work summary
    conjecture  = a formal or informal conjecture
    result      = a result proved IN THIS paper (not cited from elsewhere)
    review      = reviewing/summarizing existing knowledge
    definition  = defining a term or concept
    equation    = a key equation or formula
    application = applying a method or theorem to get a specific result
    citation    = citing or referencing prior work ([15], [Hart77], etc.)
    preview     = previewing a result that comes later in this paper
    proof       = part of a proof
    remark      = an aside or observation
    example     = a worked example or concrete instance
    figure_ref  = referencing or describing a figure/diagram

  ROLE DISAMBIGUATION (read carefully — most common errors):
  • preview vs proof — "we will prove that…", "we now show…", "in this section we establish…" → preview, NOT proof. Reserve proof for actual derivation steps (algebra, case analysis, "because X, Y follows", numbered proof step content).
  • definition vs background vs section heading — section headings (all-caps, bold, "UV/BCFW scaling", "AMPLITUDE ZEROS", "I. INTRODUCTION", "Conventions") → background, OR omit role if heading is on its own line with no defining content. Reserve definition for spans that DEFINE a math object: "Let X be...", "We define X as...", "An X is a Y such that…". A heading alone is not a definition.
  • numeric labels — a span whose entire text is just a number ("1.", "2.", "(3)") is NOT a proof step. Skip the role or use remark.

- Declarative tags (letter + chunk.tag): relationships to OTHER content
    p=proves, a=assumes, c=contradicts, e=extends, r=prerequisite
    q=equivalent, s=supports, k=special_case, x=example_of, d=data_for, v=figure_ref
- Search-class tags (uppercase + confidence a-z):
    L=logical gap, I=internal ref, S=specific external source, B=broad search
    Confidence: a=lowest (~4%), z=highest (~100%). N=no search (never output).
    IMPORTANT: L, I, and B ALWAYS take a confidence suffix (e.g. Lt, Iv, Br).
    S NEVER takes a suffix — write bare "S" because the system resolves it
    when the cited source is uploaded. This is the single most important
    rule about search-class tags: write "S" alone, never "Sa", "Sq", etc.

CONTEXT TAG QUALITY RULES (most common metadata defects):
═══════════════════════════════════════════════════════════════════

- SPECIFICITY: tag each span with what THAT SENTENCE is actually about, not the broad topic of the surrounding section. If the section is "BCFW recursion" but a sentence defines a complex shift parameter, tag it `bcfw_complex_parameter`, NOT `bcfw_recursion`. Avoid putting the same broad tag on every span in a chunk — distinct sentences should have distinct tags. Tags drive the edge graph, and every distinct concept needs its own anchor.

- NORMALIZATION: pick one canonical name per concept. Do not write `uv_scaling` on one span and `enhanced_uv_scaling` and `uv_bcfw_scaling` on others when they all refer to the same concept. Pick the shortest reasonable form (`uv_scaling`) unless the distinction is essential. Same for `hidden_zeros` vs `amplitude_zeros` vs `zero_condition` — choose one canonical form per paper.

- AGGRESSIVE GAP DETECTION (the most important rule in this prompt):
    For every equation, result, claim, definition, or derivation step that is stated without full justification IN THIS PAGE, add an L-class tag with a TYPE letter:
        Ld = missing definition (uses a concept without defining it)
        Lv = missing derivation (states a result without showing the steps)
        Lp = missing proof (asserts without proving)

    Do NOT assume the reader knows standard material. Examples that MUST be tagged:
      - "by the Euler-Lagrange equations" without deriving them → Lv
      - "Mandelstam invariants s, t, u" without defining them → Ld
      - "it follows that A = B" without showing the algebra → Lp
      - "we use the BCFW recursion" without stating BCFW → Ld
      - "this can be derived from the action principle" → Lv
      - "applying the Ward identity" → Ld + Lv
      - "as is well known" → Lp
      - "the Adler zero condition" without defining it → Ld
      - any equation that appears with "=" but no derivation chain → Lv

    EVERY chunk should produce AT LEAST one L-tag UNLESS the chunk is purely self-contained (a clean definition that defines all its own terms, prose with no math claims, or a complete proof that uses only previously-defined objects). When in doubt, ADD the tag — these are triage signals, not assertions, and downstream matching uses them to pull notes / cited papers.

    L-tag format: Ld / Lv / Lp (single letter type, no confidence suffix). Legacy form Lt (L with confidence t) is still accepted but the typed form is strongly preferred — gap matching depends on the type.

    B (broad external search): the sentence makes a substantive claim that is NOT proved here AND does NOT cite a source. If the claim is substantive and unjustified, prefer L-with-type over B. Use B only when the claim is so general it could come from any of dozens of sources.

CRITICAL RULES FOR DECLARATIVE TAGS — PRECISION OVER RECALL:
═══════════════════════════════════════════════════════════════════

- p (proves): ONLY when THIS sentence contains or IS the proof. NOT when it mentions a proof exists elsewhere.
- r (prerequisite): ONLY when the target is explicitly needed to understand THIS sentence.
- q (equivalent): ONLY when the sentence explicitly states an equivalence ("equivalent to", "if and only if").
- s (supports): ONLY when THIS sentence provides direct evidence. NOT when two ideas are merely related.
- e (extends): ONLY when THIS sentence generalizes or builds on a specific prior result.
- a (assumes): ONLY when THIS sentence explicitly relies on an assumption.

If a sentence CITES prior work ([15], [26-31], "shown in [Hart77]", "Theorem 3 of [AM]"):
  → Use role tag "citation"
  → If the citation points to ANOTHER book/paper: add search class S (bare, no suffix)
  → If the citation points to THIS book/paper (e.g. "see Section 3.2"): add search class I{a-z}
  → Do NOT use p/q/r/s declarative tags for citations

If a sentence makes a CLAIM that the text itself does NOT fully justify and does NOT cite:
  → "It can be shown that...", "One easily verifies...", "It follows that..." → Lp (missing proof)
  → "by the Euler-Lagrange equations", "from the action principle", "applying the Ward identity" → Lv (missing derivation)
  → "the Mandelstam invariants", "the BCFW shift", "the Adler zero condition" — terms used without definition → Ld (missing definition)
  → Substantive unjustified claim that could come from any of many sources → B{a-z}
  → Rule of thumb: if the reader would ask "where does this come from?" the span needs an L (with type), B, I, or S tag.

WHEN IN DOUBT: do NOT add a declarative tag (p/q/r/s...). Missing edges can be found later by the resolution pipeline. False edges pollute the graph and are hard to remove. BUT: DO add search-class tags liberally — they are triage signals, not hard assertions, and the downstream resolution pipeline is specifically designed to sort them out.
